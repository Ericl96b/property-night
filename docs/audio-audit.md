# Property Night: audio audit (current state)

Date: 2026-11-24. Read-only audit of the `main` branch at commit `46021ff`. No code was changed.

## How audio works today

- **How sounds are made:** all audio is synthesized at run time with the raw Web Audio API: oscillators plus a 1-second white-noise buffer pushed through biquad filters and gain envelopes. The project ships **no audio files** and uses **no audio library** (no Howler or similar). See the header comment in `src/audio/sound.ts:1`.
- **Where the code lives:**
  - `src/audio/sound.ts` is the only audio module. It defines the `SoundFx` interface with six effects (`dice`, `tap`, `coins`, `card`, `tock`, `sting`), a no-op `SILENT` implementation, and the `Sound` class. `Sound` holds the `AudioContext`, two gain buses (music and effects) feeding one `DynamicsCompressor` (threshold -14 dB, ratio 4), the noise buffer, two `Throttle`s, and a generative music scheduler.
  - `src/main.ts:105-114` creates one `Sound`, assigns it to `director.sound`, and unlocks it on the first `pointerdown`, `keydown` or `touchstart`, or on any gamepad button through `input.onAnyButton`. It also suspends and resumes the context on `visibilitychange`.
  - `src/director/director.ts` is the **only** gameplay caller. It turns engine `GameEvent`s into animation-queue items, and some of those items call `this.sound.*`. The UI layer (Svelte components, focus, menus) never calls audio.
  - `src/bench/testBoard.ts:182,198` calls `tock()` directly for the developer test board.
- **How sounds load and play:** nothing is loaded. Each call builds fresh oscillator, filter and gain nodes and schedules them at `ctx.currentTime + ~5-10 ms`. Before the first user gesture, and whenever the effects gain is 0, `live()` returns null and nothing is created (`sound.ts:123`). In unit tests and before `main.ts` runs, the director uses `SILENT`.
- **Volume and mixer:** there are three settings, `volumeMaster`, `volumeMusic` and `volumeEffects`. Defaults are 0.8, 0.4 and 0.8 (`src/app/settings.ts:56-58`). They are set in the Pause menu as 0-100% dropdowns in 10% steps, where 0 shows as "Off" (`src/ui/components/PauseMenu.svelte:36-40,129-135`). They reach the mixer through `applySettings` → `sound.setVolumes` (`src/main.ts:129`), so they **are wired up**.
  - `mixGains` (`sound.ts:26`) squares each slider value and multiplies by master. Music gets an extra 0.35 trim.
  - Every effect goes to the effects bus, and the music goes to the music bus.
  - There is no separate mute toggle: 0% acts as mute. There is no per-category control beyond music versus effects.
  - Unit tests cover the mixer maths (`tests/audio.test.ts`).
- **Assets:** none. There are no audio files in `public/`, `src/` or the handoff folders, so format, sample rate and file size don't apply. The noise buffer is generated at the context's sample rate (usually 44.1 or 48 kHz) and is 1 s long, mono.
- **Speed interaction:** the animation speed setting (Relaxed, Normal, Fast or Instant; `src/director/queue.ts:10`) changes timing but not pitch. At Instant speed the director plays a single dice knock and a single token tap instead of one per contact or step. When the player presses Confirm to skip, `director.skip()` calls `queue.flush()` (`queue.ts:48-57`), which runs `start()` on **every** queued item at once. Every queued `coins`, `tock`, `card` and `sting` therefore fires in the same instant.

## Infrastructure issues that would make replacing sounds harder

1. **Synthesis is hardcoded.** Every effect is a block of oscillator, noise and filter code inside a method of `Sound` (`sound.ts:167-240`). No path exists to load a file (no `fetch`, `decodeAudioData` or buffer cache), so swapping in a recorded `.ogg`/`.wav` needs a new loader and playback path, not a data change.
2. **No central sound registry or event map.** Sounds are named by method, not by ID, and the mapping from game event to sound is scattered through `director.ts`'s `switch` (`director.ts:227-397`). Adding a sound for an event means a new `SoundFx` method, a `SILENT` stub, the `Sound` implementation, and a call site.
3. **The interface is too coarse.** One `coins(amount)` serves 15+ situations, one `tock()` serves buy, trade, auction, house and hotel, and one `sting(good|bad)` serves every banner. The director passes no context (reason, payer versus payee, human versus bot, house versus hotel), so finer sounds would need interface changes at every call site.
4. **UI has no audio hook at all.** Audio is reachable only through `director.sound`. The Svelte layer, `focus.ts`, `menuStack.ts` and `InputManager` have no reference to the `Sound` instance (it is created in `main.ts:105`), so every UI sound needs new plumbing.
5. **Only two volume categories.** Master, music and effects exist; there is no UI-sound or voice/announcer bus, no per-event gain table, and no ducking or sidechain. Levels are baked as literal peak values inside each method (for example `0.12`, `0.35`, `0.16`).
6. **Stacking on skip and in batches.** `queue.flush()` (`queue.ts:48`) runs `start()` for every queued item at once, so Confirm-to-skip fires all pending `coins`, `tock`, `card` and `sting` sounds in the same instant. `queue.update` also runs up to 8 instant items per frame (`queue.ts:62`). Only `tap` and `dice` have throttles; nothing limits voices globally or per sound.
7. **Inconsistent speed handling.** At Instant speed the property-transfer `tock` is suppressed (`director.ts:295`) but build and sell `tock`s are not (`director.ts:312,316`), and the Instant tap is queued before the move rather than on landing (`director.ts:272`).
8. **No bot or human, or local-player, distinction.** Every sound fires identically for bots, with no option to quieten bot turns or emphasise "your turn".
9. **Music is code, not content.** The score is hardcoded MIDI note arrays and a fixed BPM (`sound.ts:49-57`), driven by a `setInterval` scheduler. There are no tracks, states or crossfades to swap, and the scheduler keeps running when music volume is 0.
10. **Limited tests.** Unit tests cover only `mixGains`, `coinCount` and `Throttle` (`tests/audio.test.ts`). Nothing checks which events trigger which sounds, so a refactor of the event mapping would have no safety net.
11. **Unlock and context lifecycle live in `main.ts`.** Context creation, the gesture unlock and visibility suspend live outside the audio module. Preloading assets before the first gesture would need to be designed around this.
